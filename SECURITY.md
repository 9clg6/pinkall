# Politique de sécurité

## Signaler une vulnérabilité

N’ouvrez pas de ticket public pour une vulnérabilité ou un secret exposé. Contactez les mainteneurs par un canal privé indiqué sur le profil de l’organisation qui héberge le dépôt.

Le signalement devrait inclure le composant affecté, l’impact, les étapes de reproduction et, si possible, une proposition de correction. Évitez d’inclure des données personnelles ou des secrets réels.

## Secrets exposés

Un secret commité doit être considéré comme compromis, même si le commit est ensuite supprimé. Il faut le révoquer ou le faire tourner avant de nettoyer l’historique.

## Versions prises en charge

Tant que le projet est expérimental, seule la branche principale à jour reçoit des correctifs de sécurité.
